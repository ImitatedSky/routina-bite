# Change: merge-name-and-search

## Why

新增紀錄頁上有兩個輸入框：上面的「名稱」與下面的「搜尋食物（名稱或備註）」。
使用者指出它們其實是同一件事——在名稱欄打的字，下面的食物庫就應該跟著篩選，
所以搜尋欄的功能應該併進上面那個輸入。

他是對的：使用者打的字要嘛是他要記的東西的名字，要嘛是他想找的食物。
兩個框逼他自己決定「這次算哪一種」，而那個決定對他沒有意義。

## What Changes

- **拿掉獨立的搜尋欄**。名稱欄同時就是食物庫的篩選條件（一樣比對名稱與備註）。
- 名稱還空著時：顯示「常吃」「最近」與依分類分組的食物庫（與現在相同）。
- 名稱有字時：隱藏「常吃」「最近」，只留篩選結果，區塊標題寫成「符合「beef」的食物」，
  讓篩選這件事看得見、不像畫面自己在跳。
- 食物庫頁自己的搜尋欄不受影響（那一頁沒有名稱欄，本來就需要）。

## Non-goals

- 不改食物庫頁、不改篩選的比對規則（仍是名稱或備註、不分大小寫）
