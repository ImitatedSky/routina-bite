# Design: widget-fit-by-width

## Decisions

### D98. 依「字放不放得下」決定，不依「幾格」
格子大小隨手機、桌面、格數設定而變（Pixel 5 欄一格約 76dp，4 欄約 95dp），
寫死「4 格以上」的門檻，在某些手機上剛好差一點就整組消失。
改成估算每一組字要多寬、扣掉圓環與間距，放得下才放。

估字寬不用 `Paint.measureText`：桌面用什麼字型畫我們的 TextView 不在我們控制內。
用依截圖量過的平均字寬：數字與英文 0.58、空白 0.28、中文 0.95 個字級，乘上系統字級縮放。
第一版用 0.6／1.0 估得太寬，3 格寬的營養小工具三個數字仍被藏起來，所以照實測調過。

### D99. 由多到少試，最後一階是「只留一組並置中」
每個版面列出幾種由完整到精簡的寫法，依序試到放得下為止。
「只放一組」時那一組置中，因為貼左、右邊空一塊會像漏顯示了東西。
RemoteViews 改不了 `layout_weight`，所以在兩組之間放一個 weight=1 的空 FrameLayout（RemoteViews 不收 `Space`），
跟著第二組一起顯示或隱藏：顯示時把兩組推到兩邊，隱藏時 root 的 `gravity=center` 讓唯一一組置中。

### D100. 舊桌面那圈內距只在舊版本扣
`AppWidgetHostView` 在 provider targetSdk ≥ 31 的情況下，Android 12 以上不再加預設內距。
之前一律扣 16dp，Pixel 上的 1×1 數字因此小一號、標籤被藏掉。改成依 `Build.VERSION.SDK_INT` 決定。

### D101. 窄而高用一個大環
完整版面要並排兩欄，寬度不到約 200dp 時兩欄互相擠掉。一格寬拉長、或 2×2，
改用 1×1 的圓環版面：環以短邊撐滿，中間數字依環的大小放大（上限從 22sp 放寬到 40sp），
2×2 就是一個大大的環，比擠成兩條窄欄清楚。

## Risks / Trade-offs

- [估的字寬和實際有出入] → 估法刻意偏寬一點；測試宿主（Android 9，實際可用區還比回報的小一成）上
  每個尺寸都截圖確認沒有被裁，真機只會更寬鬆
- [2×2 不再有按鈕] → 2×2 一按就開今日頁；要按鈕請拉到 3 格寬以上
