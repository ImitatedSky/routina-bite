# Change: widget-fit-by-width

## Why

v0.15.0 上線後，使用者在 Pixel 上看到：

- **一排高、3 格寬**的營養小工具，右邊空了一大塊，三個營養素明明放得下卻沒顯示
- **1×1、一排 2 格寬**還可以更好

追下去是三個原因：

1. 「要不要放第二組數字」寫死成**寬度 ≥ 250dp**。Pixel 一格約 76dp，3 格約 228dp，剛好不到。
2. 1×1 中間數字的字級，一律扣掉 Android 11 以下桌面才有的那圈 8dp 內距。Pixel 是 Android 12+，
   沒有那圈，數字被平白縮小、底下的「剩餘」標籤也被藏掉。
3. 一排 2 格寬只放得下熱量一組時，那一組貼在左邊、右邊空著，看起來像漏了東西。

另外順手發現：**一格寬拉高、或 2×2** 會被分到完整版面，兩欄在那個寬度下互相擠掉。

## What Changes

- 不再寫死幾格：**估字的實際寬度，放得下就放**，由多到少試：
  - 今日 一排：喝水放「500 / 2000」→ 只放「500」→ 不放
  - 營養 一排：「620 大卡」＋「蛋白 30」→「620 大卡」＋色點數字 →「620」＋色點數字 → 不放
  - 今日 兩排：喝水欄放得下就寫「500 / 2000 ml」，不然「500 ml」；熱量數字太寬就縮一號
  - 營養 兩排：右邊放不下「蛋白質」這些名稱就藏起來，只留色點與數字
  - 喝水 橫版：放得下整句「今天 500 / 2000 · 還差 1500」才講完整
- **只有一組時置中**，兩組時用 spacer 推到兩邊
- 1×1 的環大小只在 Android 11 以下才扣那圈內距；中間標籤的字級跟著數字放大
- **窄而高（一格寬拉長、2×2）改用一個大圓環**，不再塞完整版面
- 版本 18 / 0.15.1

## Impact

- `Widgets.kt`：`widgetSizeOf` 分桶、`contentWidthDp`、`textWidthDp`、`fitTextSp`、`ringLabelSp`；移除 `WIDGET_WIDE_DP`
- 三個 provider 的 build 函式
- `bite_widget_row.xml`、`bite_macro_widget_row.xml`（置中＋spacer）、`bite_macro_widget.xml`（名稱加 id）
- 零新權限、零新相依
